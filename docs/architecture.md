# Architecture notes

## Current foundation

The application is a React 19 + TypeScript single-page web project built with Vite. Presentation, local state, and page navigation are separated into `src/App.tsx`, the Docs, Sheets, Slides, Drive and PDF workspaces, their styles, and local storage modules. The local storage module validates persisted shapes and exposes narrow operations for workspace labels, documents, workbooks, worksheets, and cell values. `src/lib/spreadsheetEngine.ts` is an isolated expression parser/evaluator; it does not use JavaScript `eval`. The Office collaboration module creates its own Supabase browser client for existing COCCE Auth when the exact approved project and public-key config are supplied; Office collaboration RPCs are enabled in the production deployment through the Office-only schema gate; local builds remain disabled by default. The other productivity workspaces and the Team Planner remain local.

The brand asset at `public/brand/cocce-office-logo.png` is the user-provided COCCE Office logo. Its transparent alpha is preserved; the squircle silhouette and lettering are not redrawn.

## Local Docs boundary

Docs uses the MIT-licensed Tiptap/ProseMirror editor with a deliberately limited schema: paragraphs, H1–H3, bold, italic, underline, strikethrough, lists, quotes, and undo/redo. The optional `richText` field stores sanitized markup; `content` remains a plain-text search/list copy. Older drafts without usable rich text fall back to escaped text paragraphs rather than being blanked by empty/unsafe markup. The allowlist sanitizer removes all attributes and active elements before stored rich text is rendered. It preserves only rectangular, unmerged, non-nested tables with paragraph/inline cell content, capped at 20 tables per document, 50 rows × 12 columns per table, 2,000 text characters per cell, and 25,000 table-text characters total. ProseMirror transactions enforce the same limits during insertion, editing, paste, and row/column changes. Paste accepts plain text only, and HTML/file drop is disabled. Local storage failures leave saved data intact and retain failed document edits in a tab-local recovery buffer across navigation, with retry/export controls and a close-tab warning. Supported formatting exports to escaped Markdown and a limited local DOCX subset; this is not a full DOCX/PDF conversion engine. DOCX import is limited to 5 MB input, 25 MB total expanded ZIP data, 8 MB per entry, 2 MB per XML part, 256 entries, 200,000 text characters and 10,000 paragraphs. It streams and counts expanded output, rejects macro/embedded-object packages and XML document/entity declarations, does not follow package relationships or external targets, and passes imported markup through the existing allowlist sanitizer. It creates a new local document; the original file is not kept or uploaded. Simple rectangular tables retain their grid through local DOCX import/export; widths, borders, shading, and advanced table styling are simplified. Merged, nested, uneven, complex, and over-limit imported tables are flattened with warnings; malformed row/cell structures fail safely, and unsupported table markup is refused on export. Images, page layout, DOCX comment markup, tracked changes and unsupported content may be omitted with warnings. DOCX export writes only the current supported editor subset. There is no full Word/OOXML round trip, collaboration, page layout, DOCX comment import/export, tracked changes, cloud sync, or backup. Review comments are local sidecars, not shared collaboration. The optional AI panel is separate from persistence: selection edits send only selected plain text and prompt drafts only the typed brief. Full-document summarization is a distinct user action that sends bounded plain text only after an explicit per-request confirmation naming the active document and disclosing provider retention; the title, file, and document metadata are excluded. Results are previewed before insertion, and there is no automatic upload, indexing, scan, or background automation. Saved workflow recipes stay in this browser. See [Docs AI privacy and behavior](office-ai.md). No GenOffice source or separately licensed editor extension was copied.

`src/lib/docsReviewComments.ts` stores version-1 review comments under `cocce-office-docs-review-comments-v1`, scoped by workspace and document ID. It is bounded to 200 comments per document, 2,000 records and 2 MB total; a selected quote is capped at 1,000 characters and a note at 2,000. Open anchors appear as ProseMirror decorations and their positions map through edits. A comment is highlighted only while the text at its mapped range exactly matches its saved quote; changed text is retained as an unhighlighted orphan rather than attached to a possibly wrong passage. Resolve/reopen/delete mutate only this sidecar. Confirmed local document deletion removes only the matching workspace/document scope. Comment notes and quotes are not part of rich text, Markdown/DOCX exports, or AI requests. This is local review support, not OOXML comments, shared review, or tracked changes.

### Docs table header semantics

The first row uses the existing `tableHeader`/`tableCell` node distinction and can be toggled through a normal local editor transaction, undo, and autosave. The supported DOCX path preserves it through Word’s `w:tblHeader` row property, without adding bold solely because a row is a header; only explicit inline marks are serialized. Before Markdown export, Docs counts headerless tables and asks for confirmation because Markdown pipe-table output treats each first row as a header. This adds no stored HTML attributes, AI consent path, or network behavior; table alignment and width authoring remain unsupported.

## Local Sheets boundary

COCCE Sheets stores workbook cells in the current browser and supports CSV import/export plus arithmetic, cell references, ranges, comparisons, and the implemented `SUM`, `AVERAGE`, `MIN`, `MAX`, `COUNT`, `COUNTA`, `ABS`, `ROUND`, `IF`, `IFERROR`, `COUNTIF`, `SUMIF`, `AND`, `OR`, `NOT`, and `CONCAT` functions. Circular references and unsupported formulas return visible spreadsheet errors. `IFERROR` evaluates its fallback lazily and does not hide circular-reference errors; `COUNTIF` and `SUMIF` accept exact or relational criteria, with case-insensitive text matching, type-matched relational comparisons (not-equal also matches unlike types), a 256-character cap on evaluated text criteria, a 512-character formula-text cap, a 10,000-cell formula-range cap, same-shape `SUMIF` ranges, and no wildcard expansion. `SUMIF` evaluates only sum cells whose criteria rows match; errors in a matched sum cell and errors in the criteria range remain visible. CSV exports calculated formula values and prefixes formula-like text to reduce spreadsheet-formula injection risk. Grid range selection (Shift+Arrow/Shift-click) is ephemeral UI state. Copy/paste handlers act only while a grid cell is focused, use quoted TSV, and preserve raw formulas; ordinary formula/edit inputs retain native text behavior. Paste must be rectangular and fit the visible 24×12 grid, is capped at 65,536 characters total and 16,384 per cell, asks before replacing populated cells, and applies through one immutable worksheet update. The local numeric-series tool supports one selected row or column, uses its first two finite numeric cells as seeds, extends their arithmetic step, and normalizes generated values to 15 significant digits. It rejects formulas, text, dates, booleans, two-dimensional ranges, and non-finite results; it asks before replacing populated targets and performs no write when all generated values already match. Pasting and series fill each produce one atomic worksheet update. Oversized or out-of-bounds input is rejected rather than clipped. An empty clipboard is a no-op. Nothing is sent to a server; failed local saves preserve the prior saved snapshot and report an error. Version-1 data predating Sheets migrates by adding an empty workbook collection; unsupported or unreadable stored versions cannot be overwritten by this build. The local grid also supports a bounded one-sheet XLSX subset, not full Excel compatibility; see the next section.

## Bounded local XLSX interchange

`src/lib/xlsxInterchange.ts` handles `.xlsx` entirely in the browser. Import requires explicit confirmation, accepts at most 5 MB compressed data, and streams ZIP entries while enforcing a 25 MB total expanded-data ceiling, 256-entry ceiling, 8 MB per entry, and 2 MB per XML part. It resolves internal Open Packaging Convention relationships only, rejects external or orphaned relationships, unsafe paths, macro/embedded parts, malformed XML, and unsupported content, and does not upload or retain the original file. Parsing must complete before the app builds a candidate state. A successful import always creates a new workbook and worksheet in one local state write; cancellation, validation errors, or storage failure leave the existing workbook snapshot unchanged and allow the user to retry.

The import/export subset is one visible, unhidden worksheet in the existing 24×12 grid (up to 288 cells), ordinary text, finite numbers, booleans, and formulas accepted by the local expression engine whose references stay within that grid. Text/formulas are limited to 65,536 characters total and 16,384 per cell. Shared strings and inline strings are supported, but text values that look like numbers, booleans, or formulas cannot be distinguished safely by the current cell model and are refused on import. On export, only canonical numeric raw values and uppercase `TRUE`/`FALSE` are emitted as typed cells; noncanonical number-like or boolean-like strings and whitespace-only cells are refused rather than silently coerced. Multi-sheet or hidden workbooks, hidden/grouped rows or columns, merged cells, charts/drawings, macros, external links, unsupported formulas, date values and non-formula error cells, non-default cell-style assignments, malformed or out-of-grid cells, and unsupported worksheet structures are rejected before local save. Formula cells with cached error results are imported only when their formula fits the local subset; cached result types are discarded and the formula is recalculated locally. Export also requires explicit confirmation and is refused for multi-sheet workbooks or unsupported formulas. It writes a simple local XLSX containing the supported cell subset; cell styles/themes, workbook properties, row/column sizing, print/view settings, calculation-chain metadata, and cached formula results are not preserved. The imported workbook name is taken from the filename. Excel recalculates formulas when opened, and formula results may differ from the local engine. This is bounded interchange, not an Excel or OOXML compatibility engine.

## Local Slides boundary

`src/SlidesWorkspace.tsx` uses the isolated `src/lib/slidesStore.ts` model and a separate `cocce-office-slides-v1` browser-storage key. Decks carry the current local workspace ID, so the personal space and locally named workspaces show separate decks. The editor supports slide text and speaker notes, three visual themes, slide insertion/duplication/deletion/reordering, keyboard-accessible presenter controls, browser print styling, and a versioned COCCE Office Slides JSON import/export format. A per-slide `layout` field supports four text-only choices: title/content, two columns (non-empty body lines split evenly), quote, and section divider. The field is optional in version-1 inputs; legacy or invalid values normalize to title/content without altering title, body, or notes. The same layout-aware body renderer is used in the editing canvas, presenter, and print/PDF stack; print output excludes speaker notes. Layout edits use the ordinary local save/recovery and undo path. Imported decks are shape-checked and limited to 100 slides, 12,000 characters per slide field, and 5 MB per input file. Undo/redo keeps structurally shared snapshots of only the active presentation, capped at 50 edits; rapid changes to the same text field coalesce within 750 ms. Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z, and Ctrl/Cmd+Y work outside text inputs. Applying undo/redo writes through the same local-storage and tab-recovery path as ordinary edits; the in-memory history resets on reload and does not include presentation create/import/delete operations. When local storage rejects a write, the UI keeps the current edit, writes a tab-scoped recovery copy where session storage is available, and offers retry; this remains browser-local recovery, not a backup. There is no PPTX reading/writing, full layout/master designer, images or other rich objects, cloud persistence, access control, or collaboration. The print action delegates PDF creation to the browser.

## Local Drive and PDF boundary

`src/lib/driveStore.ts` stores browser-local file blobs and metadata in a separate IndexedDB database, `cocce-office-drive-local-v1`, with workspace-scoped reads, a 25 MB per-file limit, previews/downloads, rename, and reversible trash. It is not cloud storage: it has no accounts, folders, sharing links, server authorization, version history, or cross-device sync. Data may be lost when the browser's site data is cleared.

`src/PdfWorkspace.tsx` uses PDF.js to render local file bytes, extract page text for search, and place a selectable PDF.js text layer over each canvas page. `src/lib/pdfSearch.ts` returns bounded search hits with original-text ranges; `src/lib/pdfSearchHighlights.ts` maps joined-item offsets back to PDF.js text nodes and measures DOM `Range` rectangles for the current page. Those temporary overlays are normalized against the rendered page stage, cleared when search content/page changes, and recomputed after rendering, rotation, or responsive scaling. Previous/Next wraps through the first 2,000 hits, the current hit scrolls into view, and Clear search discards transient overlays. Search geometry is never persisted. `src/lib/pdfSelection.ts` captures selected text and normalizes rectangles into page coordinates so saved marks reproject after preview rotation and resizing. `src/lib/pdfAnnotationStore.ts` keeps highlight, comment, underline, and strike-through metadata in version-1 browser storage scoped by local workspace and Drive file ID. New marks carry an optional SHA-256 fingerprint of the exact source bytes; older sidecars remain readable, but unverified visual marks must be recreated before export. Underline and strike-through vector lines are regenerated by `src/lib/pdfTextMarks.ts`. Annotation additions/deletions use a 50-step session-only undo history; confirmed page clear removes its sidecar records atomically, and UI state changes only after storage succeeds. The explicit **Create annotated copy** action in `src/lib/pdfAnnotatedCopy.ts` re-reads the scoped sidecar and local source bytes only after an affirmative browser confirmation, verifies the source fingerprint, then draws supported marks as vector page content into a separate local PDF copy. PDF.js `page.view`, intrinsic rotation, and pdf-lib MediaBox/CropBox are checked for each marked page; geometry tests render synthetic copies through Poppler across in-bounds offset crops and all quarter-turn rotations. A CropBox outside its MediaBox is rejected because PDF.js and Poppler render that malformed/ambiguous geometry differently. Other limits are 25 MB input/output, 500 pages, 10,000 mark rectangles, and 14,400 user-unit physical page dimension. The output's sidecar marks are flattened visual content—not editable PDF annotation objects—and comments, quotes, and note text are excluded. The source PDF and sidecar remain unchanged; ordinary download, rotation, extraction, reorder, and merge outputs continue to omit sidecar marks. Digital signatures and advanced form behavior may not be preserved. The other pdf-lib page tools also write separate copies to the browser-local Drive store. Files, hashes, and annotations remain in the browser; no upload, remote conversion, secure sharing, or collaborative annotations are used. OCR, direct text/image editing, form creation, signatures, and secure redaction are not implemented.

## Local Vault boundary

`src/lib/vaultStore.ts` stores one encrypted Vault snapshot in its own IndexedDB database, `cocce-office-vault-local-v1`, separate from the unencrypted local Drive. Folder names, file names, MIME types, and file bytes are inside the encrypted payload; IndexedDB retains only version/algorithm metadata, a random 128-bit PBKDF2 salt, a fresh 96-bit AES-GCM nonce, a monotonic snapshot revision, timestamps, and ciphertext. Version 1 uses browser-native Web Crypto: PBKDF2-HMAC-SHA-256 with 600,000 iterations derives a non-extractable 256-bit AES-GCM key from a passphrase of at least 12 characters. AES-GCM uses its 128-bit authentication tag. Authenticated additional data binds the format, algorithms, salt, nonce, revision, and both timestamps; timestamps must be canonical UTC ISO strings, and creation cannot be later than the latest update. A new random nonce is generated for each snapshot. No passphrase or derived key is persisted by COCCE Office (browser password managers remain separate). The key and decrypted payload exist in component memory while the Vault is unlocked. Locking drops the component's references; JavaScript does not guarantee immediate memory erasure, and closing the page is not a device-integrity guarantee.

The `.coccevault` backup contains the same encrypted payload plus public format metadata. Restore verifies the passphrase and authenticated ciphertext before writing into a browser that has no Vault record. It does not contain a recovery key or permit a passphrase reset: losing the passphrase makes both the local copy and exported backups unrecoverable. A read/write IndexedDB transaction compares the current revision with the revision the tab originally unlocked; stale writes are rejected rather than overwriting newer data, but changes are not merged and the user must lock and unlock again. The browser does not have a server-side policy boundary; this is local at-rest encryption only. It does not implement enterprise access control, multiple identities/roles, secure sharing, remote access logs, file version history, automatic idle lock, biometric unlock, or WebAuthn/passkeys. Browser extensions, malware, or anyone using the device while unlocked may access plaintext. Clearing site data can remove the only copy, while deleting files cannot erase exported backups or guarantee forensic deletion of browser-storage remnants; a separately stored encrypted export is important.

## Local Team Planner boundary

`src/TeamWorkspace.tsx` and `src/lib/teamStore.ts` implement only a browser-local planning surface, persisted under the separate `cocce-office-team-local-v1` key. Department, team, project, and channel records are organizational labels, not service objects or member groups. Optional parent relationships are validated for workspace scope and cycles. Personal tasks support a title, notes, status, priority, optional due date, and an optional local project reference; assignment to people is not modeled. CRUD, archive/restore, app-wide local search, and counts are based on this browser’s actual records.

Planner state is a versioned local-storage snapshot with bounded record and field sizes. Malformed or unsupported records are not overwritten, and failed storage writes leave the previous state untouched. JSON backup/transfer is limited to 5 MB; import validates the format, schema, IDs, hierarchy, workspace references, and task/project relationships before a non-destructive merge into the active local workspace. Export/import moves a file manually and is not synchronization or a backup service. There is no authentication, member directory, invitation, role, chat, presence, notification, shared assignment, or server-side authorization in this module.

## Office Team collaboration (production integration)

`src/OfficeTeamCollaboration.tsx`, `src/lib/officeTeamApi.ts`, and `src/lib/officeTeamSupabase.ts` stage the collaboration UI and RPC wrapper for the owner's chosen architecture: use the existing COCCE Supabase Auth project and identities, without new accounts or Auth settings. Read-only Supabase project discovery identified the target as project reference `nresyncmhdybucenhxbw` at `https://nresyncmhdybucenhxbw.supabase.co`. The standalone Vite app creates its own browser client restricted to that exact project, using only a public anon/publishable key and an Office-specific browser storage key; it supports existing-account email/password sign-in only, no sign-up, and local-scope sign-out. No Auth settings, redirect allowlists, existing COCCE tables/RLS, or other shared services are changed. `.env.example` contains placeholders only; any real local verification key belongs only in an ignored local environment file, never in source or a pushed file. The production deployment enables the Office schema gate; local environments keep it false unless explicitly configured for the applied schema.

`supabase/migrations/20261101180000_office_team_collaboration.sql` was owner-approved and applied, adding only new `office_*` tables/functions/policies, and the client uses bounded polling for cross-user updates; no shared Realtime publication or service configuration is modified. `office_private` helpers are not exposed through PostgREST. Authenticated users receive Office-table `SELECT` grants constrained by new Office RLS; writes go through fixed-search-path SECURITY DEFINER RPCs with workspace/participant checks. Profile-returning reads are SECURITY INVOKER and use only `profiles.id`, `username`, `full_name`, `profile_photo_url`, `is_vip`, and `vip_expires_at`, subject to existing COCCE profile RLS and the Office invoker guard that hides a profile if either account blocked the other. All RPC VIP-expiry outputs use `timestamp without time zone`, matching the existing profile column; the client interprets offset-free values as local time rather than converting them to `timestamptz`. Presence is also filtered by profile visibility; hidden status is unavailable rather than falsely offline. Email and phone are not selected. Invitation creation rejects every existing membership, and invitation acceptance rejects an existing membership instead of upserting it to active; only the authorized explicit administrator restore operation may reactivate a suspended member. Existing Auth settings, tables, policies/RLS, profile rows, blocked-user rows, apps, and storage are not altered.

Office person rows show the vector shield/check adapted from the read-only COCCE source `lib/widgets/vip_badge.dart`; a badge appears only when `is_vip=true` and `vip_expires_at` is absent or future, matching `Profile.isVipActive`. Presence is workspace-scoped and heartbeats every 25 seconds across active spaces; hidden tabs report away, and a heartbeat older than 90 seconds displays offline. The same identity row is used for members, search, invitations, direct conversations, messages, and notifications. Local Team Planner data remains browser-only and has no person/assignment model.

The approved Office-only migration is applied, and controlled end-to-end checks passed with three existing COCCE test accounts for workspace creation, invitation acceptance/decline, role changes and ownership transfer, conversations/messages, notifications, presence, and authorization guards. The disposable test workspace and its Office rows were deleted. The production gate is separate from the local default. The client uses bounded polling, not genuine Realtime collaboration. The known 13-table shared-project security finding remains unapproved and untouched. The rollback permanently deletes Office collaboration rows and drops Office tables/schema/functions; its `CASCADE` clauses may also drop later-created dependent objects. It has not been run and must only be used intentionally after reviewing the target and data-loss consequences.

## Reference project assessment

The public GenOffice repository uses React/TypeScript but its apps are principally Electron desktop applications. Its Docs surface uses Tiptap/ProseMirror and OOXML patching; Sheets uses Univer plus a Rust sidecar; Slides uses React/Konva with PPTX engines; PDF uses PDF.js/PDFium/pdf-lib. The renderer depends on Electron IPC, filesystem access, native tools, and desktop process boundaries, so the app cannot be copied into a browser build unchanged. Only specific portable packages should be evaluated, with separate review for all licenses and transitive notices. The `ee/` directory is separately licensed and must not be used in a hosted service without the required authorization.

2. Put all Office-only records in additive `office_` tables with RLS and workspace/resource authorization. Do not alter existing COCCE tables, triggers, Edge Functions, auth behavior, Firebase setup, or storage rules.
3. Create Office-owned upload authorization and storage mappings through a server-side boundary; never expose Bunny credentials to the browser and never share existing application paths.
4. Use separate, audited services/workers for document conversion and native engine tasks. Browser-facing editors must be tested for format round-trips rather than claiming full DOCX/XLSX/PPTX fidelity based on the desktop app.
5. The bounded AI route in `api/office-ai.js` verifies existing-account Auth, accepts only an explicit selection or prompt-only draft, applies request/output limits and a per-user cap, and uses a server-side OpenRouter key with one fixed `:free` model and provider fallback disabled. It rejects mismatched/positively priced responses and reports temporary free-model outages instead of selecting a paid model; provider-specific data retention is disclosed in [Docs AI behavior](office-ai.md). 6. Treat localization, collaboration, notifications, Vault protection, and release qualification as first-class workstreams—not UI badges.


## Docs table cell-range selection

The Docs table toolbar creates ProseMirror `CellSelection` ranges for the active row, column, or entire simple table using cell-node positions. The existing inline mark commands (bold, italic, underline, and strikethrough) apply through ordinary editor transactions; the resulting rich-text edit uses the same local autosave, undo/redo, and tab-recovery path. Selection is ephemeral and adds no persisted cell attributes. Review-comment data remains in its separate local sidecar and is neither rewritten nor exported by these actions. The bounded rectangular DOCX subset is unchanged and preserves supported inline marks; cell shading, alignment, custom widths, merging, and full Word fidelity remain unsupported.


Cell-range selections are excluded from excerpt-AI capture and local review-comment creation. Prompt-only drafts continue to send only the typed brief. Full-document summaries can still include table text only through their existing separate affirmative confirmation; an AI preview cannot be inserted while a table-cell range is active.


## Docs local Find & Replace boundary

`src/lib/docsFindReplace.ts` walks ProseMirror text nodes and returns local document positions; it does not concatenate paragraphs/cells or search comment sidecar data. It caps queries at 128 characters, replacements at 1,000 characters, scanned document text at 200,000 characters, and results at 2,000. Literal matches are case-insensitive by default. Each replacement is revalidated against current text; output size and all ranges are validated before a transaction is built. Plain-text inserted content preserves the matched inline marks, and Replace All applies all changed ranges in one ordinary editor transaction for the existing undo/autosave/recovery path. The UI requires explicit confirmation before Replace All. No fetch/API, AI, export-schema, storage-key, or cloud behavior is added.
Replacement ranges are rechecked against one current ProseMirror text node and its current inline-mark set; ranges that cross marks, paragraphs, or cells, or carry altered marks, are rejected before any transaction step. Search results are tied to the current document object/revision, and switching document scope clears the query and replacement before the new content can be navigated.


## Sheets formula-fill boundary

`fillFormula` in `src/lib/spreadsheetEngine.ts` accepts only a one-dimensional selection in the existing visible 24×12 grid, capped at 24 cells, whose first (top/left) cell contains a formula accepted by the local parser. It shifts relative A1 row/column coordinates by the destination offset while retaining `$` row and column anchors. A bounded scanner skips double-quoted formula strings (including escaped quotes), so A1-looking text is unchanged. Cross-sheet/external references, unsupported names/structured references/functions, malformed formulas, source or translated references outside the grid, and formulas above the existing 512-character cap are rejected. All translated formulas validate before the helper returns an immutable cell map; the UI asks before replacing populated targets and passes the complete result to one existing `updateWorksheetCells`/local-storage write. Save failures preserve the previous saved snapshot. Generated formulas round-trip only when they already fit the existing bounded XLSX subset; no interchange features were added. Formula fill is included in the bounded per-worksheet session history documented below.

## Local Sheets session history boundary

`src/lib/spreadsheetHistory.ts` stores compact immutable per-cell deltas for changed raw values in component memory, keyed to the current workbook and worksheet. Each worksheet is capped at 50 undoable actions; rapid formula-bar/grid edits to the same cell coalesce within 750 ms. History entries are recorded only after the existing `onState` local-save callback accepts the full state. Undo/redo restores the exact raw strings and formulas through the existing immutable worksheet-update path, and that restored state is persisted before the history stack advances. A failed write therefore leaves both the saved cell map and the undo/redo position unchanged. No-op updates do not add a step or clear a redo branch; a new accepted edit after undo clears redo. The stack is not in `PreviewState`, local storage, XLSX, or any server request and resets on reload or leaving the workbook editor; switching worksheets within the editor keeps each worksheet's bounded stack.

The supported history scope is cell/formula edits, one rectangular TSV paste, one numeric-series fill, or one formula fill per accepted edit. Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z, and Ctrl/Cmd+Y work outside input, select, textarea, `[role="textbox"]`, and contenteditable targets so native text editing is not intercepted. Workbook/worksheet title changes, adding/selecting sheets, creating/importing/exporting workbooks, and other structural operations are deliberately excluded. XLSX parsing and export semantics are unchanged.
