# Office Team collaboration — applied schema and release review

## Chosen identity and database boundary

The owner selected the existing COCCE Supabase Auth project and identities, with only new COCCE Office-specific tables/functions. Read-only Supabase project discovery identified the existing COCCE project as reference `nresyncmhdybucenhxbw`, canonical URL `https://nresyncmhdybucenhxbw.supabase.co`. Existing COCCE tables, RLS policies, Auth settings, profile data, storage, other apps, and shared services remain out of scope.

The standalone Vite app owns a browser client restricted to that exact project. It uses only a public anon/publishable key and a separate Office browser storage key. Users can sign in with email/password to existing COCCE accounts only: there is no sign-up or account-creation flow. Office sign-out uses local scope and does not sign out other COCCE app sessions. No Auth settings, redirect allow-lists, or providers have been changed. The committed `.env.example` has placeholders only; any real public key belongs only in the ignored, permission-restricted `.env.local`.

`VITE_OFFICE_TEAM_SCHEMA_READY` is enabled only for the approved production deployment; `.env.example` keeps the local default `false`. The Auth client uses an Office-local browser session and calls the Office RPCs only when that gate is enabled.

## Prepared SQL and behavior

`supabase/migrations/20261101180000_office_team_collaboration.sql` was owner-approved, applied, and recorded as migration `20261101180000`; its matching rollback under `supabase/rollback/` has not been run. The migration creates only new `office_*` tables/functions, Office-owned RLS policies, and private Office authorization helpers. It does not create a new Auth provider or alter `auth.users`, existing COCCE relations/RLS, `profiles`, `blocked_users`, Auth settings, storage, shared Realtime, or another shared service. Cross-user updates use bounded polling: messages every 5 seconds, active workspace data every 15 seconds, and workspace lists, incoming invitations, and notifications every 30 seconds.

Profile-returning RPCs select only the needed identity/badge fields (`id`, `username`, `full_name`, `profile_photo_url`, `is_vip`, and `vip_expires_at`); profile email and phone are not selected. The existing COCCE `profiles.vip_expires_at` column is `timestamp without time zone`. All eight RPC outputs that expose it now declare that same timezone-free type, preserving COCCE's local-time semantics. The Office client represents this as `OfficeLocalTimestamp`; JavaScript parses the offset-free timestamp as local time before comparing it to local `Date.now()`. No conversion to `timestamptz` is performed. PostgreSQL documents the `RETURN QUERY` row-type contract in its [PL/pgSQL control-structure reference](https://www.postgresql.org/docs/current/plpgsql-control-structures.html) and declared output coercion for [SQL-language functions](https://www.postgresql.org/docs/current/xfunc-sql.html); the Office RPC declarations now match the existing source column type directly. Profile visibility remains subject to existing COCCE profile RLS and an Office-side `SECURITY INVOKER` check that hides a profile when either account blocked the other. This adds no changes to `public.blocked_users` or its policies.

Invitation creation now rejects any existing workspace membership, active or suspended. Accepting an invitation locks and checks for an existing membership and fails rather than upserting that membership to `active`; this also protects against a previously pending invitation. An authorized administrator must use the explicit `office_manage_member(..., 'restore')` action to restore a suspended member. Presence rows remain filtered through the profile-visibility check; when a profile is hidden, the UI says “Status unavailable” rather than inventing “offline.”

The badge is a vector adaptation of the Super App's `VipBadge` painter at `/workspace/COCCE_Super_App/lib/widgets/vip_badge.dart` (read-only source inspection; no asset is involved). It uses the same gold-to-orange shield, dark inset, and gold checkmark. It appears only when the server-returned `is_vip` is true and `vip_expires_at` is absent or later than the current local time, matching `Profile.isVipActive` in `/workspace/COCCE_Super_App/lib/models/profile.dart`.

Office presence is workspace-scoped. The client sends 25-second authenticated heartbeats to active workspaces and polls the active workspace every 15 seconds; hidden tabs report “Away,” and a heartbeat older than 90 seconds displays “Offline.” Chat polls every 5 seconds; workspace lists, incoming invitations, and notifications poll every 30 seconds. This is not genuine Realtime synchronization. Local Team Planner objects remain browser-only and have no people or assignments.

## Rollback and data loss

The rollback script is deliberately destructive: it drops the Office collaboration tables, functions, trigger, and `office_private` schema, permanently deleting all stored Office workspaces, memberships, invitations, messages, notifications, and presence. Its `DROP ... CASCADE` clauses can also remove later-created objects that depend on those Office objects. It has not been run and is not a harmless downgrade; review the target and take any required backup before any future rollback. It does not alter existing COCCE tables, policies, Auth settings, shared Realtime, or other shared services.
