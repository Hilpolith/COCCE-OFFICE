# COCCE Office — collaboration workspace

This private, isolated React/TypeScript project is the COCCE Office browser app. Most productivity data remains browser-local; Office Team collaboration is server-backed for existing COCCE accounts, and the Docs AI studio contacts its server route only after a user-triggered action.

## What works

The responsive interface uses a frosted Liquid Glass treatment guided by the supplied UI references. The supplied COCCE Office logo artwork is preserved with transparent alpha; the dashboard hero, sidebar, Vault header, favicon, and home-screen icon use transparent squircle assets. The app supports local workspace labels, six themes plus an accent color, and local document search

**Docs** uses Tiptap/ProseMirror for editable rich text with headings, bold/italic/underline, strikethrough, lists, quotes, undo/redo, local autosave, and Markdown export of supported formatting. It imports and exports a bounded local DOCX subset: text, headings 1–3, common text marks, simple lists, and rectangular tables up to 50 rows × 12 columns. Tables are capped at 20 per document, 2,000 text characters per cell, and 25,000 table-text characters total. Simple tables round-trip with their grid; merged, nested, uneven, complex, or over-limit imported tables are flattened with a warning, and unsupported export tables are refused. Import is limited to 5 MB compressed and 25 MB expanded, always creates a new local draft, omits unsupported parts, ignores external link targets, and rejects macro/embedded-object packages. Export is capped at 5 MB and rejects drafts over 200,000 characters, 10,000 paragraphs, or 2 MB of formatted markup before packing. The original file is not retained or uploaded. Its optional AI writing studio offers selection-based summaries, proofreading, quality checks, clarity/conciseness edits, expansion, key points, action lists, outlines, email rewrites, custom workflows, prompt-only draft starters, and a full-document summary behind a separate explicit confirmation. AI results are previewed before insertion; selection actions send only the selected excerpt, drafts send only the typed prompt, and confirmed full-document summaries send bounded plain text only. No file or document metadata is sent. Legacy plain-text drafts remain readable; pasted content is inserted as plain text and stored markup is sanitized before it is rendered. Failed document saves remain visible and recoverable within the current tab across navigation, with retry and export controls; that temporary buffer is not a backup.

**Sheets** supports local workbooks and worksheets, cell/formula editing, a tested formula subset (arithmetic, references, ranges, and common functions), CSV import/export, bounded keyboard navigation, rectangular range selection, local arithmetic-series fill, and a bounded XLSX subset. Shift+Arrow or Shift-click extends a range; Ctrl/Cmd+C and Ctrl/Cmd+V copy or paste local TSV, preserving raw formulas and correctly quoting tabs, quotes, and newlines. Pasting asks before replacing populated cells and is applied as one local save; oversized, ragged, or out-of-grid pastes are rejected without clipping. The series tool fills one selected row or column from its first two finite numeric cells, extends their arithmetic step, normalizes generated values to 15 significant digits, and asks before replacing populated targets. Formula, text, date, and boolean seeds, two-dimensional ranges, and non-finite results are rejected without a partial update. Clipboard ranges are limited to the visible 12×24 grid, 65,536 characters total, and 16,384 characters per cell. CSV export writes formula results as values and prefixes formula-like text to reduce spreadsheet-formula injection risk. XLSX import creates a new local workbook only after the user confirms and the entire package passes validation; export also requires a fidelity confirmation. Interchange is limited to one visible 24×12 worksheet (288 cells), ordinary text, finite numbers, booleans, and same-sheet formulas supported by the local engine. Import is capped at 5 MB compressed, 25 MB expanded, 256 ZIP entries, 8 MB per entry, 2 MB per XML part, 65,536 text/formula characters total, and 16,384 per cell. Multi-sheet/hidden workbooks, hidden or grouped rows/columns, merged cells, charts, macros, external links, unsupported formulas, date/error cells, non-default cell-style assignments and ambiguous text types are refused before saving. Export emits canonical numeric raw values and uppercase TRUE/FALSE as typed cells, but refuses noncanonical numeric/boolean-like strings and whitespace-only values rather than coercing them. Cell styles/themes, workbook properties, row/column sizing, print/view settings, calculation-chain metadata and cached formula results are not retained; the imported workbook name comes from the filename. Export is not full Excel compatibility. Formula, parser, clipboard, series, XLSX, upload-size, and export-area limits have synthetic unit coverage. Charts, pivots, collaboration, and cloud sync are not included.

**Slides** supports browser-local text decks scoped to the current local workspace: create and rename decks, edit slide titles, line-based body text and speaker notes, choose among three visual themes, add/duplicate/delete/reorder slides, and present with keyboard navigation. Undo/redo covers the active presentation's content, notes, title/theme, and slide add/duplicate/delete/reorder actions; rapid typing in a field is grouped. Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z, and Ctrl/Cmd+Y work outside text fields. The stack is capped at 50 edits for the current session; undo/redo results autosave locally, but the history itself resets after a reload. Creating, importing, or deleting a presentation is not included in that stack. Decks can be imported and exported in the COCCE Office Slides JSON format and printed or saved as PDF through the browser's own print dialog. Failed local-storage writes get a tab-scoped recovery copy when session storage is available.

**Drive** stores files in this browser's IndexedDB, scoped to the current local workspace. It supports multi-file upload (25 MB per file), previews for supported content, download, rename, reversible trash, permanent deletion, and recovery. This is local browser storage, not cloud storage or secure sharing.

**PDF** opens local PDFs with PDF.js, renders pages with a selectable text layer, and searches extracted page text across up to 2,000 matches. Search hits receive temporary page-positioned overlays; Previous/Next wraps through the results, the active hit is scrolled into view, and Clear search removes only the temporary query highlights. Overlays are recalculated for the rendered page after rotation or responsive resizing and are never saved as annotations. Selected text can be highlighted or given a comment; those saved annotations remain in browser local storage, scoped by local workspace and Drive file, and are not embedded in the PDF. The pdf-lib tools create new local copies for page rotation, extraction, reordering, and merging. Source PDFs are not overwritten.

**Vault** stores files and protected-folder names in a separate browser IndexedDB database. Before persistence, its contents are encrypted with browser-native AES-GCM (256-bit); the key is derived locally with PBKDF2/SHA-256 (600,000 rounds). Vault format, revision, salt, nonce, and timestamps are authenticated; revision checks reject stale saves from another tab instead of silently overwriting newer data. COCCE Office does not store or send the passphrase; browser password managers are separate. A versioned encrypted backup can be exported and restored into a browser with no existing Vault (25 MB/file, 50 MB total, 80 MB backup limit).

**Team Planner (local only)** supports workspace-scoped departments, teams, projects, channels, and personal tasks with status, priority, due date, and notes. Items can be edited, archived, searched, and backed up or transferred through a validated versioned JSON file. It uses a separate browser-storage key and does not change Docs, Sheets, Slides, Drive, or Vault records. This is a private planning surface—not a member directory, message service, invitation system, shared task list, or cloud sync feature.

**Office Team collaboration** uses a separate UI/API and the applied Office-only `office_*` schema for workspaces, membership/roles, invitations, private text direct/group/channel conversations, in-app notifications, and workspace-scoped presence. The standalone Vite app creates its own browser client for the existing COCCE Supabase project, using only that project's public anon/publishable key; it supports password sign-in for existing COCCE accounts only, with no signup, and Office sign-out is local to this browser. The production build enables the Office data gate through a separate production-only environment setting; `.env.example` remains false by default for local development. The `.env.example` file contains placeholders only; any real local public key belongs only in the ignored local environment file and must not be committed. The migration only adds Office objects/policies and bounded polling for cross-user updates (messages every 5 seconds; active-space data every 15 seconds; workspaces, invitations, and notifications every 30 seconds). No `supabase_realtime` publication or other shared service is changed; existing COCCE tables, RLS, Auth settings, and storage stay untouched. Profile reads use existing COCCE RLS and an Office-side invoker guard that hides a profile if either account blocked the other; only ID, username, display name, avatar, `is_vip`, and `vip_expires_at` are selected, never profile email or phone. VIP expiry outputs retain the source PostgreSQL `timestamp without time zone` and the client compares them as local timestamps, matching COCCE profile semantics. The Super App's gold/orange shield/check VIP badge appears only for `is_vip=true` with no expiry or a future expiry. Invitations are rejected for any existing membership, and accepting a pending invitation cannot restore a suspended member; an authorized administrator must use the explicit restore action. Presence is per workspace: heartbeats go to active workspaces every 25 seconds, hidden tabs show away, and stale heartbeats show offline after 90 seconds; blocked profile status is marked unavailable. The approved migration is applied and controlled collaboration flows have been tested; the rollback remains unused and is deliberately destructive. The client uses bounded polling, not genuine Realtime collaboration. This does not sync or assign local planner tasks. Email/external invitations, push notifications, attachments, audio/video, reactions, message editing/deletion, and read receipts are not included.

## Important limits

Office Auth can sign in an existing COCCE account in an independent browser-local session; it does not create accounts or alter shared Auth settings. The applied Office schema supports membership, invitations, roles, messaging, notifications, and presence in the separate collaboration module; the production-only gate is enabled for the approved release while local examples stay off. Google OAuth, cloud storage, upload authorization, full DOCX fidelity, full XLSX/PPTX compatibility, an autonomous/background workflow runner, document-wide AI indexing, and a multilingual catalog are not included. Team Planner items and tasks remain on this browser unless manually moved in a JSON backup; no people are represented, and tasks cannot be assigned to another user. The Vault is local encryption at rest, not enterprise security: it has no server-side access control, secure sharing, access logs, file history, automatic idle lock, biometric unlock, or passkey recovery. Losing the passphrase makes the encrypted data unrecoverable; backups also require the original passphrase. Browser extensions or malware can access content while unlocked; clearing browser site data can erase the local copy; removing an item does not erase prior backups or guarantee forensic deletion of browser-storage remnants. If multiple tabs save at once, stale writes are rejected and require a lock/unlock before retry; there is no merge. PDF OCR, secure sharing, cloud collaboration, and embedding PDF annotations into the source file are not implemented; browser-local highlights and comments are separate metadata and can be lost if this browser's site data is cleared. Drive does not have folders, sharing, version history, or remote sync. Slides is not a PowerPoint editor: its portable format is COCCE Office Slides JSON, not PPTX; it has no images, charts, shapes, transitions, or collaboration. Browser print-to-PDF is not a full PDF authoring workflow. Docs remains a limited local-first rich-text editor, not a Word/OOXML format engine; its DOCX support is a bounded, lossy text-and-formatting subset. Complex or over-limit tables are flattened with warnings; simple bounded tables are editable locally and can round-trip in DOCX. Images, page layout, tracked changes, comments, and collaboration are not implemented. Its AI actions are user-triggered and previewed; full-document summaries require a separate confirmation, are limited to plain text, and do not enable indexing or background scans. See [Docs AI privacy and behavior](docs/office-ai.md) for the request limits and 55-day/no-training disclosure. Sheets provides CSV plus a bounded local one-sheet XLSX subset, not full Excel compatibility or collaboration; XLSX formatting, dates, charts, pivots, macros, multi-sheet books, and advanced formulas are not supported. The app is not an enterprise-security platform. Only Office Team collaboration stores shared collaboration data; other modules remain browser-local except for explicitly triggered Docs AI requests and should not be used for collaborative or enterprise-sensitive work. Other modules store their local data in this browser and it can be cleared by the browser.

## Isolation and integration

Local workbooks, Slides, Drive files, PDF operations, and the Team Planner use browser storage. The separate Office Auth client connects only to the existing COCCE Supabase project with a public anon/publishable key and a separate browser-local session; the user must sign in to an existing account. The Office-only migration is applied, and the production deployment uses the dedicated schema gate; local examples remain disabled by default. The committed `.env.example` contains placeholders only; do not commit a real local env file or key. No existing COCCE app, Auth setting, table, policy, or shared service was changed. Review [the architecture notes](docs/architecture.md), [integration boundaries](docs/integration-boundaries.md), [Docs AI privacy and behavior](docs/office-ai.md), and [implementation log](docs/implementation-log.md) for the implemented boundaries.

The upstream GenOffice repository is primarily an Electron desktop product; its Electron IPC/native-engine assumptions are not directly portable to a browser. The separately licensed `ee/` directory was not copied.

Provided open-source dependency license texts are preserved in [third-party notices](public/third-party-notices.txt) and ship with the built application.

## Release status

The Office Team collaboration slice is released through the existing `cocce-office` Vercel project using its existing Vercel SSO configuration; aliases, domains, and protection settings are unchanged. This remains a limited collaboration surface, not a full enterprise productivity suite: Docs, Sheets, Slides, Drive, PDF, Vault, and Team Planner remain browser-local, and cloud file storage, external/email invitations, push notifications, attachments, audio/video, reactions, message editing/deletion, and read receipts are not included.


The verified [Office capability matrix and roadmap](docs/office-capability-roadmap.md) distinguishes current local-first features from missing Microsoft Office/GenOffice compatibility and future AI work.
