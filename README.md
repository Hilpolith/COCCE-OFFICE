# COCCE Office — collaboration workspace

This private, isolated React/TypeScript project is the COCCE Office browser app. Most productivity data remains browser-local; Office Team collaboration is server-backed for existing COCCE accounts, and the Docs AI studio contacts its server route only after a user-triggered action

## What works

The responsive interface uses a frosted Liquid Glass treatment guided by the supplied UI references. The supplied COCCE Office logo artwork is preserved with transparent alpha; the dashboard hero, sidebar, Vault header, favicon, and home-screen icon use transparent squircle assets. The app supports local workspace labels, six themes plus an accent color, and local document search

**Docs** uses Tiptap/ProseMirror for editable rich text with headings, bold/italic/underline, strikethrough, lists, quotes, undo/redo, local autosave, and Markdown export of supported formatting. It imports and exports a bounded local DOCX subset: text, headings 1–3, common text marks, simple lists, and rectangular tables up to 50 rows × 12 columns. Tables are capped at 20 per document, 2,000 text characters per cell, and 25,000 table-text characters total. Simple tables round-trip with their grid; merged, nested, uneven, complex, or over-limit imported tables are flattened with a warning, and unsupported export tables are refused. Import is limited to 5 MB compressed and 25 MB expanded, always creates a new local draft, omits unsupported parts, ignores external link targets, and rejects macro/embedded-object packages. Export is capped at 5 MB and rejects drafts over 200,000 characters, 10,000 paragraphs, or 2 MB of formatted markup before packing. The original file is not retained or uploaded. Local review comments anchor to selected text, can be resolved, reopened, or deleted, and stay in a separate browser-only sidecar excluded from exports and AI requests. Its optional AI writing studio offers selection-based summaries, proofreading, quality checks, clarity/conciseness edits, expansion, key points, action lists, outlines, email rewrites, custom workflows, prompt-only draft starters, and a full-document summary behind a separate explicit confirmation. AI results are previewed before insertion; selection actions send only the selected excerpt, drafts send only the typed prompt, and confirmed full-document summaries send bounded plain text only. No file or document metadata is sent. Legacy plain-text drafts remain readable; pasted content is inserted as plain text and stored markup is sanitized before it is rendered. Failed document saves remain visible and recoverable within the current tab across navigation, with retry and export controls; that temporary buffer is not a backup.

Docs tables can switch the first row between a semantic header and ordinary cells; the bounded DOCX subset preserves that distinction. Markdown pipe tables require a header, so exporting a table without one asks before treating its first row as the header. Alignment and column sizing remain unsupported.

**Sheets** supports local workbooks and worksheets, cell/formula editing, a tested local formula subset (arithmetic, references, ranges, and common functions including `IFERROR`, `COUNTIF`, and `SUMIF`), CSV import/export, bounded keyboard navigation, rectangular range selection, local arithmetic-series fill, relative-reference formula fill, 50-step per-worksheet session undo/redo for cell edits, TSV paste and both fill actions, and a bounded XLSX subset. Shift+Arrow or Shift-click extends a range; Ctrl/Cmd+C and Ctrl/Cmd+V copy or paste local TSV, preserving raw formulas and correctly quoting tabs, quotes, and newlines. Pasting asks before replacing populated cells and is applied as one local save; oversized, ragged, or out-of-grid pastes are rejected without clipping. The series tool fills one selected row or column from its first two finite numeric cells, extends their arithmetic step, normalizes generated values to 15 significant digits, and asks before replacing populated targets. Formula, text, date, and boolean seeds, two-dimensional ranges, and non-finite results are rejected without a partial update. Clipboard ranges are limited to the visible 12×24 grid, 65,536 characters total, and 16,384 characters per cell. CSV export writes formula results as values and prefixes formula-like text to reduce spreadsheet-formula injection risk. XLSX import creates a new local workbook only after the user confirms and the entire package passes validation; export also requires a fidelity confirmation. Interchange is limited to one visible 24×12 worksheet (288 cells), ordinary text, finite numbers, booleans, and same-sheet formulas supported by the local engine. `COUNTIF` and `SUMIF` support exact criteria and simple relational operators; text comparisons are case-insensitive; relational comparisons require matching value types, while not-equal criteria count unlike types as different. Evaluated text criteria are limited to 256 characters, formula text to 512 characters, formula ranges to 10,000 cells, and wildcards are literal. `SUMIF` requires a same-shape sum range and evaluates only matching sum cells. `IFERROR` evaluates its fallback only when the first expression errors and does not mask circular references. Import is capped at 5 MB compressed, 25 MB expanded, 256 ZIP entries, 8 MB per entry, 2 MB per XML part, 65,536 text/formula characters total, and 16,384 per cell. Multi-sheet/hidden workbooks, hidden or grouped rows/columns, merged cells, charts, macros, external links, unsupported formulas, date values and non-formula error cells, non-default cell-style assignments and ambiguous text types are refused before saving. Formula cells with cached error results are imported only when their formula fits the local subset; cached result types are discarded and the formula is recalculated locally. Export emits canonical numeric raw values and uppercase TRUE/FALSE as typed cells, but refuses noncanonical numeric/boolean-like strings and whitespace-only values rather than coercing them. Cell styles/themes, workbook properties, row/column sizing, print/view settings, calculation-chain metadata and cached formula results are not retained; the imported workbook name comes from the filename. Export is not full Excel compatibility. Formula, parser, clipboard, series, XLSX, upload-size, and export-area limits have synthetic unit coverage. Charts, pivots, collaboration, and cloud sync are not included.

**Slides** supports browser-local text decks scoped to the current local workspace: create and rename decks, edit slide titles, line-based body text and speaker notes, choose among three visual themes and four per-slide text layouts (title/content, two columns, quote, and section divider), add/duplicate/delete/reorder slides, and present with keyboard navigation. Two-column layout splits non-empty body lines evenly; the other layouts change styling without rewriting slide text or notes. Layouts are saved in local storage and JSON, rendered in the editor and presenter, and included in the browser print/PDF stack. Legacy or unknown JSON layout values fall back to title/content. Undo/redo covers the active presentation's content, notes, title/theme, layout, and slide add/duplicate/delete/reorder actions; rapid typing in a field is grouped. Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z, and Ctrl/Cmd+Y work outside text fields. The stack is capped at 50 edits for the current session; undo/redo results autosave locally, but the history itself resets after a reload. Creating, importing, or deleting a presentation is not included in that stack. Decks can be imported and exported in the COCCE Office Slides JSON format and printed or saved as PDF through the browser's own print dialog. This text-only layout slice does not add images, masters, or PPTX support. Failed local-storage writes get a tab-scoped recovery copy when session storage is available.

**Drive** stores files in this browser's IndexedDB, scoped to the current local workspace. It supports multi-file upload (25 MB per file), previews for supported content, download, rename, reversible trash, permanent deletion, and recovery. This is local browser storage, not cloud storage or secure sharing.

**PDF** opens local PDFs with PDF.js, renders pages with a selectable text layer, and searches extracted page text across up to 2,000 matches. Search hits receive temporary page-positioned overlays; Previous/Next wraps through the results, the active hit is scrolled into view, and Clear search removes only the temporary query highlights. Search overlays are recalculated after rotation or responsive resizing and are never saved. Selected text can be highlighted, underlined, struck through, or given a comment; saved marks use normalized page coordinates and remain in browser local storage scoped by local workspace and Drive file. A 50-step session undo and confirmed current-page clear operate on those local annotations. Text marks reproject through page rotation and resize. Sidecar marks never change the original PDF or appear in ordinary downloads/rotation/extraction/reorder/merge copies. **Create annotated copy** is a separate, explicitly confirmed local action that binds visual marks to the exact source PDF bytes and flattens verified highlights, underlines, and strike-throughs into page content. The marks are visual—not editable PDF annotation objects—and comments, quotes, and note text are excluded. This copy is limited to 25 MB, 500 pages, and 10,000 mark rectangles; encrypted/malformed PDFs, unverified legacy marks, unsupported page geometry/rotation, and CropBoxes extending beyond the MediaBox are refused rather than risking cross-viewer misalignment. Digital signatures and advanced form behavior may not be preserved. The source bytes and local sidecar remain unchanged, and nothing is uploaded. The pdf-lib tools also create separate local copies for page rotation, extraction, reordering, and merging.

**Vault** stores files and protected-folder names in a separate browser IndexedDB database. Before persistence, its contents are encrypted with browser-native AES-GCM (256-bit); the key is derived locally with PBKDF2/SHA-256 (600,000 rounds). Vault format, revision, salt, nonce, and timestamps are authenticated; revision checks reject stale saves from another tab instead of silently overwriting newer data. COCCE Office does not store or send the passphrase; browser password managers are separate. A versioned encrypted backup can be exported and restored into a browser with no existing Vault (25 MB/file, 50 MB total, 80 MB backup limit).

**Team Planner (local only)** supports workspace-scoped departments, teams, projects, channels, and personal tasks with status, priority, due date, and notes. Items can be edited, archived, searched, and backed up or transferred through a validated versioned JSON file. It uses a separate browser-storage key and does not change Docs, Sheets, Slides, Drive, or Vault records. This is a private planning surface—not a member directory, message service, invitation system, shared task list, or cloud sync feature.

**Office Team collaboration** uses a separate UI/API and the applied Office-only `office_*` schema for workspaces, membership/roles, invitations, private text direct/group/channel conversations, in-app notifications, and workspace-scoped presence. The standalone Vite app creates its own browser client for the existing COCCE Supabase project, using only that project's public anon/publishable key; it supports email/password account registration, sign-in, Google OAuth when enabled, email confirmation, password recovery, and first-workspace onboarding through the existing COCCE Auth project. Office sign-out is local to this browser. The production build enables the Office data gate through a separate production-only environment setting; `.env.example` remains false by default for local development. The `.env.example` file contains placeholders only; any real local public key belongs only in the ignored local environment file and must not be committed. The migration only adds Office objects/policies and bounded polling for cross-user updates (messages every 5 seconds; active-space data every 15 seconds; workspaces, invitations, and notifications every 30 seconds). No `supabase_realtime` publication or other shared service is changed; existing COCCE tables, RLS, Auth settings, and storage stay untouched. Profile reads use existing COCCE RLS and an Office-side invoker guard that hides a profile if either account blocked the other; only ID, username, display name, avatar, `is_vip`, and `vip_expires_at` are selected, never profile email or phone. VIP expiry outputs retain the source PostgreSQL `timestamp without time zone` and the client compares them as local timestamps, matching COCCE profile semantics. The Super App's gold/orange shield/check VIP badge appears only for `is_vip=true` with no expiry or a future expiry. Invitations are rejected for any existing membership, and accepting a pending invitation cannot restore a suspended member; an authorized administrator must use the explicit restore action. Presence is per workspace: heartbeats go to active workspaces every 25 seconds, hidden tabs show away, and stale heartbeats show offline after 90 seconds; blocked profile status is marked unavailable. The approved migration is applied and controlled collaboration flows have been tested; the rollback remains unused and is deliberately destructive. The client uses bounded polling, not genuine Realtime collaboration. This does not sync or assign local planner tasks. Email/external invitations, push notifications, attachments, audio/video, reactions, message editing/deletion, and read receipts are not included.

## Important limits

Office Auth supports email/password registration and sign-in in an independent browser-local session, plus Google OAuth and password recovery when those providers are enabled in the existing COCCE Auth project. New users may need to confirm their email before signing in, then create their first Office workspace. The app does not alter shared Auth settings. The applied Office schema supports membership, invitations, roles, messaging, notifications, and presence in the separate collaboration module; the production-only gate is enabled for the approved release while local examples stay off. Google OAuth, cloud storage, upload authorization, full DOCX fidelity, full XLSX/PPTX compatibility, an autonomous/background workflow runner, document-wide AI indexing, and a multilingual catalog are not included. Team Planner items and tasks remain on this browser unless manually moved in a JSON backup; no people are represented, and tasks cannot be assigned to another user. The Vault is local encryption at rest, not enterprise security: it has no server-side access control, secure sharing, access logs, file history, automatic idle lock, biometric unlock, or passkey recovery. Losing the passphrase makes the encrypted data unrecoverable; backups also require the original passphrase. Browser extensions or malware can access content while unlocked; clearing browser site data can erase the local copy; removing an item does not erase prior backups or guarantee forensic deletion of browser-storage remnants. If multiple tabs save at once, stale writes are rejected and require a lock/unlock before retry; there is no merge. PDF OCR, direct text/image editing, secure sharing, cloud collaboration, and embedding annotations into exported PDFs are not implemented; browser-local highlights, comments, underlines, and strike-through marks are separate overlays and can be lost if site data is cleared. Drive does not have folders, sharing, version history, or remote sync. Slides is not a PowerPoint editor: its portable format is COCCE Office Slides JSON, not PPTX; it has no images, charts, shapes, transitions, or collaboration. Browser print-to-PDF is not a full PDF authoring workflow. Docs remains a limited local-first rich-text editor, not a Word/OOXML format engine; its DOCX support is a bounded, lossy text-and-formatting subset. Complex or over-limit tables are flattened with warnings; simple bounded tables are editable locally and can round-trip in DOCX. Images, page layout, tracked changes, DOCX comment import/export, and cloud collaboration are not implemented; review comments are local selected-text sidecars and are excluded from document exports. Its AI actions are user-triggered and previewed; full-document summaries require a separate confirmation, are limited to plain text, and do not enable indexing or background scans. See [Docs AI privacy and behavior](docs/office-ai.md) for the request limits and 55-day/no-training disclosure. Sheets provides CSV plus a bounded local one-sheet XLSX subset, not full Excel compatibility or collaboration; XLSX formatting, dates, charts, pivots, macros, multi-sheet books, and advanced formulas are not supported. The app is not an enterprise-security platform. Only Office Team collaboration stores shared collaboration data; other modules remain browser-local except for explicitly triggered Docs AI requests and should not be used for collaborative or enterprise-sensitive work. Other modules store their local data in this browser and it can be cleared by the browser.

## Isolation and integration

Local workbooks, Slides, Drive files, PDF operations, and the Team Planner use browser storage. The separate Office Auth client connects only to the existing COCCE Supabase project with a public anon/publishable key and a separate browser-local session; the user must sign in to an existing account. The Office-only migration is applied, and the production deployment uses the dedicated schema gate; local examples remain disabled by default. The committed `.env.example` contains placeholders only; do not commit a real local env file or key. No existing COCCE app, Auth setting, table, policy, or shared service was changed. Review [the architecture notes](docs/architecture.md), [integration boundaries](docs/integration-boundaries.md), [Docs AI privacy and behavior](docs/office-ai.md), and [implementation log](docs/implementation-log.md) for the implemented boundaries.

The upstream GenOffice repository is primarily an Electron desktop product; its Electron IPC/native-engine assumptions are not directly portable to a browser. The separately licensed `ee/` directory was not copied.

Provided open-source dependency license texts are preserved in [third-party notices](public/third-party-notices.txt) and ship with the built application.

## Release status

The Office Team collaboration slice is released through the existing `cocce-office` Vercel project using its existing Vercel SSO configuration; aliases, domains, and protection settings are unchanged. This remains a limited collaboration surface, not a full enterprise productivity suite: Docs, Sheets, Slides, Drive, PDF, Vault, and Team Planner remain browser-local, and cloud file storage, external/email invitations, push notifications, attachments, audio/video, reactions, message editing/deletion, and read receipts are not included.


The verified [Office capability matrix and roadmap](docs/office-capability-roadmap.md) distinguishes current local-first features from missing Microsoft Office/GenOffice compatibility and future AI work.


**Docs table range authoring:** In a simple table, select the current row, current column, or all cells, then use the existing bold, italic, underline, or strikethrough controls across that selection. These are ordinary local editor edits covered by undo/redo and save/recovery; selection itself is transient. The bounded DOCX table subset is unchanged. Cell shading, alignment, custom widths, merging, and full Word compatibility are not included.
Cell-range selection is for formatting only; it does not count as selected text for AI excerpt actions or local review comments. Table text is sent to AI only through the separate full-document summary confirmation, and a preview cannot be applied while a cell range remains active.


## Docs local Find & Replace

Docs now searches and replaces literal text locally in the active document. Search is case-insensitive by default, with an optional case-sensitive mode; Previous/Next and Enter/Shift+Enter navigate through up to 2,000 matches. A query is limited to 128 characters, replacements to 1,000 characters, and a search scans documents up to 200,000 text characters. Matches are found within individual text runs, so they do not span inline-format boundaries, paragraphs, or table cells; table-cell text is searchable, while review-comment notes are excluded. Replacements are inserted as plain text, retain the replaced text's inline marks, and use the ordinary Docs autosave/recovery and undo/redo path. Replace All shows an explicit match-count confirmation and applies one undoable local edit; it never sends document text over the network or invokes AI. This does not add tracked changes or DOCX comment support.
Find state belongs only to the active document; switching documents clears the query and replacement so old matches cannot carry over.


## Sheets local formula fill

Select one row or column (up to 24 visible cells) with a supported formula in its first cell, then choose **Fill formula**. Relative A1 references move down or right; mixed and absolute `$` anchors remain fixed as specified. Formula-like text inside quoted strings is left unchanged. Cross-sheet/external references, unsupported or malformed syntax, out-of-grid references, and formulas over 512 characters are refused before any update. Populated targets require confirmation; valid results are applied in one local worksheet save and remain within the existing XLSX formula subset. Formula fill participates in the bounded session-only cell history described below; browser-local save-failure handling remains in effect.

## Sheets session Undo/Redo

Undo/Redo is local and session-only: it keeps up to 50 accepted cell-content actions per worksheet in memory, and the history itself is not written to browser storage. It covers cell and formula-bar edits, rectangular TSV paste, numeric-series fill, and formula fill; rapid edits to the same cell coalesce within 750 ms. Undo and redo each use the same local save path as an ordinary edit; if a save fails, the saved cell state and history step remain unchanged. Ctrl/Cmd+Z undoes, while Ctrl/Cmd+Shift+Z and Ctrl/Cmd+Y redo when the grid is active; shortcuts are left to text inputs and contenteditable areas. Switching worksheets keeps each worksheet's in-memory history, but reload or leaving the workbook editor clears it. Workbook or worksheet names/structure and import/export are not undoable. This does not change the existing XLSX subset or store history in the workbook.


## Industry workbench (local preview)

The sidebar puts Docs, Sheets, Slides, PDF, Drive and Vault under one **Documents** group and lists ten industry choices separately under **Office suites**. The current shared workbench creates a local office profile and a simple sector-labeled work register with stage history and search. It can hand off to the existing Office Team creation flow; only the resulting workspace ID is associated locally, and register items are not shared with team members. This is a non-sensitive-data preview stored in unencrypted browser storage, not a complete industry suite, accounting/payroll system, clinical/government record system, or approved statutory integration. See the [capability roadmap](docs/office-capability-roadmap.md#industry-workbench-local-preview-tranche--2026-11-05) and [platform expansion backlog](docs/office-platform-expansion.md#industry-office-preview-status--2026-11-05) for boundaries and remaining work.
